# Build Notes

The app bundle version is generated by `scripts/build-native-app.sh` from its defaults or explicit environment overrides.

## Layout

- `Sources/ImageViewerNative/main.swift` - AppKit, Metal rendering, playback, menus, save/load, and Finder Open With handling.
- `Assets/` - icon source and generated `.icns`.
- `scripts/build-native-app.sh` - the release bundle builder and source of truth for bundle metadata.
- `scripts/create-dmg.sh` - DMG installer builder.
- `scripts/verify-dmg.sh` - DMG installer verifier.
- `MediaFlow.app` - generated app bundle, intentionally ignored by git. Rebuild it after source, icon, document type, or bundle metadata changes.
- `dmg_output/` - generated DMG output, intentionally ignored by git.
- `docs/ICON_GENERATION.md` - prompt and selection rules for generating a SessionFlow-style MediaFlow icon.
- `README.md` and `STATUS.md` - user-facing usage notes and current implementation state.
- `AGENTS.md` - project memory for future Codex sessions.

## Release Focus

- TV, spare-screen, and fullscreen live memory-wall usage.
- Floating Flow Library for a larger media pool than the visible wall.
- Maximum visible item control for readable ambient layouts.
- Round-robin and random rotation through the library.
- Optional duplicate random slots during random rotation.
- Add Files, drag/drop ingest, and Add From Photos entry points.

## Build

Run from the project root:

```sh
./scripts/build-native-app.sh
```

The script:

- builds SwiftPM in `release` mode with whole-module optimization;
- keeps SwiftPM and Clang caches under `.build` so sandboxed runs are easier to repeat;
- recreates `MediaFlow.app`;
- generates `Contents/Info.plist` with the configured bundle version and media document types;
- copies `Assets/AppIcon.icns`;
- copies `CHANGELOG.md` and `LICENSE` into `Contents/Resources` for the app dialogs;
- strips local symbols from the executable;
- signs and verifies the app bundle.

By default the script uses ad-hoc signing. For a Developer ID build:

```sh
SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./scripts/build-native-app.sh
```

Override bundle metadata only when intentionally cutting another build:

```sh
MARKETING_VERSION="$RELEASE_VERSION" BUILD_NUMBER="$RELEASE_BUILD" ./scripts/build-native-app.sh
```

`scripts/build-native-app.sh` increments the tracked `BUILD_NUMBER` file on every build unless `BUILD_NUMBER` is explicitly supplied. Local/non-public builds show the build number in the app UI; public release builds hide it. Linked git worktrees also get their worktree folder name embedded in the app metadata for local identification.

For public release metadata that hides local build/worktree details in-app:

```sh
PUBLIC_RELEASE=true MARKETING_VERSION="$RELEASE_VERSION" ./scripts/build-native-app.sh
```

## Run

Open the generated app:

```sh
open "MediaFlow.app"
```

To refresh Finder's Open With registration after rebuilding:

```sh
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f "MediaFlow.app"
```

## DMG

Create an installer DMG:

```sh
./scripts/create-dmg.sh
```

The script creates a versioned DMG under `dmg_output/` with `MediaFlow.app`, an `Applications` symlink, and a Finder layout. The layout stores a hidden `.background/dmg-background.png` with a light Finder-readable background and the MediaFlow-style cyan/violet drag arrow.

If Finder AppleScript is blocked in automation, build a plain DMG without custom layout:

```sh
SKIP_FINDER_LAYOUT=true ./scripts/create-dmg.sh
```

Verify the latest DMG:

```sh
./scripts/verify-dmg.sh
```

To sign the DMG container with Developer ID, pass the same signing identity:

```sh
SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./scripts/create-dmg.sh
```

## Self-Updates

The app menu exposes **Check for Updates...**. It checks:

```text
https://api.github.com/repos/kibermaks/MediaFlow/releases/latest
```

Release requirements:

- GitHub Release tag should match the app version.
- Attach a `.dmg` or `.zip` containing `MediaFlow.app`.
- Public repositories work without credentials.
- While the repository is private, launch the app with `MEDIAFLOW_GITHUB_TOKEN` or `GITHUB_TOKEN` in its environment if you need update checks to see private releases.

## Notarization

For public distribution, use Developer ID signing and notarize both the app and the DMG:

```sh
xcrun notarytool store-credentials "MediaFlow" \
  --apple-id "your@email.com" \
  --team-id "TEAMID" \
  --password "app-specific-password"

SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./scripts/build-native-app.sh
./scripts/notarize.sh "MediaFlow.app" MediaFlow
SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./scripts/create-dmg.sh
./scripts/notarize.sh "path/to/generated/MediaFlow.dmg" MediaFlow
./scripts/verify-dmg.sh
```

The keychain profile can be any stored `notarytool` profile for the same Apple Developer team.

## Verification

Expected command:

```sh
./scripts/build-native-app.sh
```

Expected result: release builds complete without AVFoundation deprecation warnings. Sandboxed automation may still print a SwiftPM user-level cache warning before the build starts; that warning is environmental and not from project source.

Useful checks:

```sh
plutil -p "MediaFlow.app/Contents/Info.plist"
codesign --verify --deep --strict "MediaFlow.app"
./scripts/verify-dmg.sh
git status --short
```

## Public Release Nuances

- The local build uses ad-hoc signing. That is fine for local testing, but public distribution should use Developer ID signing, hardened runtime, notarization, and stapling.
- `spctl` may warn on the local ad-hoc app even when `codesign --verify` passes.
- `dmg_output/` is ignored; upload DMGs to GitHub Releases instead of committing them.
- Generated `.app` bundles are ignored. Keep binaries in GitHub Releases instead of source commits.
- The repository now has an MIT license.

## Easy To Forget

- Do not hand-edit `MediaFlow.app/Contents/Info.plist` for permanent changes; edit `scripts/build-native-app.sh` and rebuild.
- Finder Open With support lives in both `Info.plist` document types and `AppDelegate` open-file handlers.
- Saved playback files use encrypted local paths. Moving source media breaks restore for those items.
- Per-file A-B histories and quality profiles are stored in `~/Library/Application Support/MediaFlow/`.
- Before cutting a release, rebuild the app and DMG so release artifacts match the Swift source and generated metadata.
